camo v2 architecture wiki

This page is the human mirror of v2/resources/registry/. The registry is the source of truth. This page repeats the same node ids (resource_id, module_id, edge id) so a reader can map a paragraph back to a machine-checked entry.

Entry points

  • CLI binary: v2/shell/bin_entry/camo.mjs -> v2/shell/cli/main.mjs
  • Service binary: v2/shell/bin_entry/browser-service.mjs -> v2/services/browser_service/main.mjs
  • Doctor: camo doctor -> v2/shell/doctor/main.mjs

Layers

L0 protocol design

Wire formats and version envelopes. Owns v2/protocol/versions/, v2/protocol/middleware/, v2/protocol/serde/.

No business logic. No resource truth. Everything passes through here on the way in/out.

L1 contract design

Per-resource builder/parser. The type lock lives here. Owns v2/contracts/ws_messages/, v2/contracts/http_messages/, v2/contracts/error_envelope/, v2/contracts/requests/, v2/contracts/responses/, v2/contracts/operations/.

L2 service design

Single truth owner per resource. Each service module is named after the resource(s) it owns. Owns v2/services/<resource>/.

Modules: profile, session, lock, container, subscription, page_runtime, display, autoscript, progress_event, browser_service.

L3 transport design

WS, HTTP, daemon, client. Owns v2/transports/ws/, v2/transports/http/, v2/transports/daemon/, v2/transports/client/.

L4 command design

One handler per command id. Loads from v2/commands/registry/. Owns v2/commands/builtins/, v2/commands/registry/, v2/commands/parsers/, v2/commands/docstrings/.

L5 shell design

Process entry, dispatch, doctor. Owns v2/shell/cli/, v2/shell/bin_entry/, v2/shell/doctor/.

Forbidden cross-layer patterns

  • L5 importing L2 directly: hard fail.
  • L4 importing L0 directly (must use L1 contracts): hard fail.
  • L3 importing L4 (reverse flow): hard fail.
  • Commands or transports opening files outside a service: hard fail.

Checklist

  1. Resource truth: each resource_id has exactly one truth_owner.
  2. Module ownership: each source file is in exactly one module's owned_paths.
  3. Imports: cross-module imports must hit a declared edge; reverse edges are forbidden.
  4. Gate: every verification_gate in registry has a real gate script under v2/gates/registry_gates/.
  5. CI: every gate runs in CI on push.
