Adding a new gate

  1. Create the gate script under v2/gates/<group>/<name>.mjs.
  2. Add a verification doc at v2/docs/verification/<name>.md.
  3. Register the gate in this index.
  4. Wire it into v2/gates/run-all.mjs or a separate CI step.
  5. Add at least one positive and one negative test.

Promote to active

When the v2 module for a resource lands and all its forbidden_paths are physically absent from v1, the resource status flips to active and the corresponding per-resource gate turns into a hard CI gate (via --strict). Hard guard 22b: never cite a design entry as live truth.
